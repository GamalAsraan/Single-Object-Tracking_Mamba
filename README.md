# Dockerized TrackingMamba Inference

## 1. Project Purpose
This project provides a fully Dockerized inference pipeline for **TrackingMamba** video tracking. It is optimized for GPU-accelerated inference without training-specific dependencies.

## 2. Folder Setup
Before running inference, ensure your local directory structure is correctly populated:
- **`models/`**: Place your compiled model checkpoint here (e.g., `models/TrackingMamba_best.pth.tar`).
- **`data/`**: Place your video files or datasets here.
- **`outputs/`**: All generated CSV or JSONL files will be dumped here.

*(Note: When using Docker Compose or the CLI commands below, these folders are mounted securely into the container).*

## 3. Build the Image
To build the Docker image locally, run:
```bash
docker build -t trackingmamba-infer:latest .
```

## 4. Single Video Inference
Run tracking on a single video file using a predefined initial bounding box:
```bash
docker run --gpus all \
  -v $(pwd)/models:/models:ro \
  -v $(pwd)/data:/data:ro \
  -v $(pwd)/outputs:/outputs \
  trackingmamba-infer:latest \
  python -m runtime.infer_video \
  --video /data/video.mp4 \
  --init-bbox 536,551,226,142 \
  --checkpoint /models/TrackingMamba_best.pth.tar \
  --output /outputs/boxes.csv
```

## 5. AIC Manifest Inference
For batch inference over an entire dataset mapped by a JSON manifest:
```bash
docker run --gpus all \
  -v $(pwd)/models:/models:ro \
  -v $(pwd)/data:/data:ro \
  -v $(pwd)/outputs:/outputs \
  trackingmamba-infer:latest \
  python -m runtime.infer_manifest \
  --manifest /data/metadata/contestant_manifest.json \
  --sample-sub /data/metadata/sample_submission.csv \
  --video-root /data \
  --checkpoint /models/TrackingMamba_best.pth.tar \
  --output /outputs/submission.csv \
  --source video
```

## 6. Benchmark Latency
To check if the tracker is achieving your latency targets (e.g., <=30ms / frame):
```bash
docker run --gpus all \
  -v $(pwd)/models:/models:ro \
  -v $(pwd)/data:/data:ro \
  -v $(pwd)/outputs:/outputs \
  trackingmamba-infer:latest \
  python -m runtime.benchmark_latency \
  --video /data/video.mp4 \
  --init-bbox 536,551,226,142 \
  --checkpoint /models/TrackingMamba_best.pth.tar \
  --frames 300 \
  --warmup 20
```

## 7. Expected Inputs
- **Video Path**: Absolute or mounted path to an `.mp4` or other video file format supported by OpenCV.
- **Init BBox**: Bounding box initialized on frame 0, strictly formatted as a string of floats: `x,y,w,h`.
- **Manifest File**: Required for batch AIC inference. Must be a JSON containing a split (e.g., `"public_lb"`) holding dictionaries with at minimum `"video_path"`, `"annotation_path"`, and `"n_frames"`.

## 8. Output Formats
- **`boxes.csv`**: Frame-by-frame tracker output for single video inference. Contains `frame_idx, x, y, w, h, latency_ms`.
- **`submission.csv`**: Competition-ready batch output format generated by manifest inference, matched directly to your `sample_submission.csv` template.

## 9. Troubleshooting
- **CUDA not visible**: Ensure your host machine has the NVIDIA Container Toolkit installed, and you are using the `--gpus all` flag or Docker Compose `deploy.resources` configs.
- **Checkpoint not found**: Verify that your checkpoint file exists in the host's `./models` folder and matches the filename passed to `--checkpoint`.
- **`mamba_ssm` import error**: The custom `mamba_ssm` or `causal_conv1d` wheels may not have installed correctly during the Docker build. Re-check the `docker build` logs for pip errors.
- **Triton RMSNorm crash**: This typically means the custom patched `models_mamba.py` (which introduces the pure PyTorch `RMSNorm` fallback and sets `fused_add_norm=False`) was not correctly copied into `/app/lib/models/trackingmamba/`.
- **OpenCV cannot open video**: Usually indicates an ffmpeg or missing video codec issue. Verify your file is a valid mp4, and that the Docker base image successfully installed `ffmpeg` and `libsm6`.
